# Testing findcrypt

This guide is for anyone working ON findcrypt — running the suite, reading the
fixtures, hunting for bugs, and extending the database. For using the tool, see
the [README](README.md).

## Quickstart

```bash
git clone https://github.com/kn1ght073/findcrypt.git
cd findcrypt
npm install

npm run build        # CLI tests run against the built bundle (dist/)
npm test             # everything: 170 tests across 14 files, a few seconds
```

Useful variants:

```bash
npx vitest                     # same as npm test
npx vitest test/authenticity.test.ts     # one file
npx vitest -t "disambiguation"           # tests matching a name
npx vitest watch               # re-run on every save
npm run fixtures               # regenerate fixtures from first principles
npm run fixtures:check         # verify committed fixtures match a fresh run
npm run typecheck              # tsc --noEmit
npm pack --dry-run             # what would ship to npm
```

CI runs the same thing on Node 18/20/22/24 across Ubuntu, macOS and Windows.

## The suite map

| File | What it proves | Representative cases |
|---|---|---|
| `authenticity.test.ts` | every db.ts constant equals its **published standard value**, re-derived inside the test (GF(2^8) math for AES, BigInt square roots for SHA-2, sine table for MD5, curve equation for secp256k1) | secp256k1 G proven on-curve: `y² = x³ + 7 mod p` |
| `scanner.test.ts` | each signature matches its fixture at the planted offset; BE/LE patterns are per-word mirrors; noise finds nothing; caps and context work | 64-match cap + truncation flag |
| `disambiguation.test.ts` | the MD5/SHA-1 shared-initial-words trap: SHA-1 occludes the MD5 echo **at the same offset only**; a genuine MD5 and a both-algorithms binary both survive | raw scan sees both; pipeline output has no echo |
| `boundaries.test.ts` | constants at offset 0 / EOF / shifted by one / back to back; degenerate inputs; scanner options; 2 MB noise under 5 s | a file that IS exactly the S-box |
| `entropy.test.ts` | Shannon entropy against hand-computable cases; windowed profiling; classification thresholds | all-same-bytes = 0.0, uniform = 8.0 |
| `strings.test.ts` | ASCII/UTF-16LE extraction, minimum length, caps | boundary runs |
| `inference.test.ts` | each verdict rule fires exactly when its conditions hold | `packed-or-custom` requires ≥ 7.9 entropy |
| `verdicts.test.ts` | end-to-end scenarios → the exact analyst verdicts, in confidence order | wallet combo → `wallet-crypto` |
| `cli.smoke.test.ts` | happy paths: help/version/scan/noise/empty/stdin/JSON/Markdown | exit codes 0/1/2 |
| `cli.matrix.test.ts` | the abuse matrix: bad flag values, directories, unreadable files, unicode names, multi-file runs, contradictory flags | `--min-entropy 9` → exit 2 |
| `output-contract.test.ts` | the JSON/Markdown **schema**: every field present, offsets in bounds and sorted, zero ANSI escapes even with `FORCE_COLOR=1`; the CJS build is requireable | `offset + matchLength ≤ size` |
| `fixtures-drift.test.ts` | committed fixtures are byte-identical to a fresh generation — and the detector itself is self-tested by tampering | one flipped byte → CI failure |
| `realworld.test.ts` | the tool works on real software: the Node runtime (statically-linked OpenSSL), system libcrypto, `/bin/ls`, and this repo's own source | Node binary → 12+ signatures, exit 0 |

## The fixtures (`test/fixtures/`)

Every fixture is **deterministic** — generated by `scripts/gen-fixtures.mjs`
from a seeded PRNG and first-principles constant derivations:

- `fixture-<id>.bin` — 256 bytes of noise, the pattern, 256 bytes of noise.
  The planted offset and exact bytes are recorded in `manifest.json`.
- `scenario-*.bin` — multi-constant files for verdict testing
  (wallet, legacy crypto, ARX, packed noise, plain text). Described in
  `scenarios.json`.
- `noise.bin`, `empty.bin` — negative controls.

`npm run fixtures:check` regenerates everything in memory and byte-compares
against the committed files. It runs in CI **before** the tests, so a generator
change without re-running `npm run fixtures` can never slip through.

The generator doubles as living documentation: it contains the derivation of
every constant (why the AES S-box is what it is, why SHA-256 starts with
`6a09e667`, why TEA uses `0x9E3779B9`).

## Bug-hunting on your own machine

The suite pins known behavior; here is how to find NEW problems. Anything that
crashes, prints a wrong offset, exits with the wrong code, or emits broken JSON
is a bug — open an issue with the file and command.

**1. Fuzz with real randomness** (the committed noise is seeded, so use fresh
entropy):

```bash
for size in 1 3 15 4095 4096 4097 65536 1048576; do
  head -c $size /dev/urandom > /tmp/fz.bin
  ./dist/cli/main.js /tmp/fz.bin > /tmp/out.txt 2>/tmp/err.txt
  echo "size=$size exit=$? out=$(wc -c < /tmp/out.txt) err=$(wc -c < /tmp/err.txt)"
done
```
Expected: exit 1 (no fingerprints in random data), no stderr output, run time
scales roughly linearly.

**2. Weird inputs:**

```bash
./dist/cli/main.js .                          # directory      -> exit 2
./dist/cli/main.js /dev/null                  # empty device   -> exit 1
./dist/cli/main.js /dev/zero                  # endless zeros  -> hangs? (256 MB cap protects you — check the error)
head -c 300000000 /dev/urandom > /tmp/big.bin # ~286 MB
./dist/cli/main.js /tmp/big.bin               # over the cap   -> exit 2, clear message
printf '\x63\x7c\x77\x7b' > /tmp/t.bin        # 4-byte partial S-box -> exit 1
./dist/cli/main.js "$(printf 'weird \t name \n .bin')"   # hostile filename
ln -s /tmp/loop /tmp/loop 2>/dev/null; ./dist/cli/main.js /tmp/loop
```

**3. Real binaries — your results should look like this:**

```bash
./dist/cli/main.js "$(which node)"            # OpenSSL tables: 12+ signatures, exit 0
ldd "$(which openssl)" | grep -o '/[^ ]*libcrypto[^ ]*'   # find the real crypto library
./dist/cli/main.js "$(ldd "$(which curl)" | grep -o '/[^ ]*libssl[^ ]*' | head -1)"
./dist/cli/main.js /bin/ls                    # usually nothing: exit 1
```

**4. Output validity under flags:**

```bash
./dist/cli/main.js --json "$(which node)" | jq empty && echo "valid JSON"
./dist/cli/main.js --json --no-strings "$(which node)" | jq '[.findings[].offsets[]] | length'
FORCE_COLOR=1 ./dist/cli/main.js --json test/fixtures/fixture-tea-delta.bin | grep -c $'\x1b'   # want 0
./dist/cli/main.js --json test/fixtures/fixture-tea-delta.bin test/fixtures/noise.bin | jq '.results | length'  # want 2
```

**5. Semantics to challenge:** scan a file containing AES S-box + S-box
inverse back to back — does the verdict explain encrypt+decrypt? Plant MD5's
IV immediately followed by SHA-1's fifth word (`c3d2e1f0`) — the disambiguation
tests say what must happen. Concatenate two fixtures — both must be reported
with exact offsets.

## Adding a signature (the whole loop)

1. Add the entry (pure data) to `src/signatures/db.ts` — both byte orders if
   it is a word table (`wordSizeBytes` + second pattern).
2. Run `npm run fixtures` — the generator picks it up, plants a fixture, and
   prints the pattern block for db.ts; commit the fixture + manifest.
3. `test/scanner.test.ts` picks the new id up **automatically** from
   `manifest.json` (per-signature positive test), and
   `authenticity.test.ts` fails until you add the independent derivation of
   the constant to `EXPECTED` — that is deliberate: a new signature must come
   with proof of its bytes.
4. `npm test` — everything green, including the drift check.

## Writing a new test

Copy the pattern of the closest existing file. Conventions:

- tests import from `../src/...` (library) or spawn `dist/cli/main.js` (CLI);
  CLI suites are `describe.skipIf(!hasBuild)` so `npx vitest` works before a
  build — CI always builds first;
- deterministic inputs only: use the committed fixtures, or a local seeded
  PRNG (see `boundaries.test.ts`) — never `Math.random()` or `Date.now()`;
- assert exact values (offsets, exit codes, verdict ids), not vague
  `toBeTruthy()`;
- if a test encodes INTENDED behavior that looks odd (e.g. bare `--` is
  rejected), say so in a comment so future-you does not "fix" it accidentally.

## Exit codes (the contract)

| Code | Meaning |
|---|---|
| 0 | at least one fingerprint found |
| 1 | scanned fine, no fingerprints |
| 2 | operational error: missing/unreadable file, directory, oversized input, bad flag |

Scripts should rely on this: `findcrypt file && investigate || echo clean`.
